## Rules for RED phase

Per Beck TDD + test-list-discipline:

1. Every test in the list above starts as `[ ]` pending.
2. Author each test file with the `# test-list:` block at top matching this doc's per-file section.
3. Every test function fails initially — either because the class does not exist yet (imports fail) OR because the assertion targets behavior that has not been implemented.
4. Full vitest run must show ALL 50 new tests RED before any src/ file changes.
5. Existing tests must stay GREEN through the RED phase (no regression).
6. Test file naming convention: `<subject>.test.ts` for units; `<flow>-integration.test.ts` for e2e.
7. Test names include the UC extension ID or risk fold code where applicable, e.g., `it('UC Ext 6a — refuses symlink at user-scope target', ...)`.

## Cross-cutting concerns satisfied

Per GRASP decomposition audit table:

- **Test isolation** — every test uses `mkdtempSync` + `afterEach rmSync` for a fresh fixture (existing pattern in `tests/init.test.ts:71-78`)
- **HOME override** — tests that exercise user-scope routing set a per-test HOME fixture via env manipulation; assertions check the fixture dir, not the operator's real home
- **No network** — every test runs offline against local files; no `gh api` calls in the harness
- **Deterministic** — settings.json fixture is a checked-in copy of v0.40.0 verbatim; content_hash pinned; no drift risk
