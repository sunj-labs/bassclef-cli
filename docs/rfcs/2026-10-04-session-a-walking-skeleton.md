# RFC adversarial — Session A walking skeleton

Three outside lenses. Each tries to kill the walking skeleton or force a reshape. Authoring luminaries (Cockburn + Torvalds + Beck) do not sit on the council.

## Scope under review

Walking skeleton PR 1: Dockerfile.lite-adopter + invariants library + nightly workflow matrix + /interpret-input driver + cli#305 Exhibit-A anchor + minimal /personas stub. PRs 2-5 grow /personas, /jtbd-tasks, /launch --local, full-chain path-contract.

## John Carmack — ship fast, pay less

Lens: Is this infrastructure actually needed? Could we skip Docker entirely?

**F-JC-1 — HIGH — Docker runtime may be over-engineered.** GitHub Actions runs ubuntu and macOS natively. Drivers that test skill behavior could run on `runs-on: macos-latest` + `runs-on: ubuntu-latest` matrix. No Dockerfile. No container build time. No local operator `run-lite-container.sh`. Testing lite surface on real adopter OS is MORE faithful than inside a container. Disposition options: (a) scrap Dockerfile, use GHA OS matrix; (b) keep Dockerfile for local operator runs only, use OS matrix for CI; (c) keep as planned. **Fold:** take option (b). PR 1 ships Dockerfile for local operator debugging + GHA OS matrix for CI. Container is operator convenience, not CI dependency. Saves ~5 min per nightly run; adds OS fidelity.

**F-JC-2 — MED — 5 PRs across one session is 2x the overhead of 1 PR.** Each PR costs CI minutes, review attention, merge cycle. Could Session A ship as 2 PRs instead? PR 1 = runtime + /interpret-input + cli#305. PR 2 = /personas + /jtbd-tasks + /launch + chain driver bundled. Disposition options: (a) 5 atomic PRs per plan; (b) 2 PRs bundled per class; (c) 3 PRs (runtime + edge drivers + chain). **Fold:** keep (a). Plan doc explicitly names stacked atomic. Operator confirmed agent-merges-within-scope. 5 PRs are reviewable; 2 bundled PRs break revert path. No change.

## Michael Nygard — will this fail silently in prod?

Lens: What breaks nightly in a way nobody notices?

**F-MN-1 — HIGH — Nightly red every night → operator fatigue → signal rot.** R-B4 fold says exit 3 = expected-RED. But over 60 days, operator stops reading the nightly email. When upstream ships a cure and driver flips GREEN, nobody notices for days. The RED-GREEN rhythm Beck promises breaks when GREEN never fires in-session. Disposition options: (a) nightly posts GREEN-flip to a Slack channel; (b) nightly updates a dashboard file in repo showing current RED/GREEN per driver; (c) nightly opens a ticket when any driver flips. **Fold:** take option (b). PR 1 ships `docs/nightly-status.md` auto-generated by workflow. Operator reads one file to see which drivers flipped GREEN overnight. Low-noise signifier (Norman convergent lens).

**F-MN-2 — MED — Container image build cache rot.** `node:20-slim` tag floats. Container runs today may differ from container runs in 60 days. Debugging flake is painful. Disposition options: (a) pin node:20-slim to digest `sha256:...`; (b) rebuild image weekly; (c) accept drift. **Fold:** take option (a). PR 1 pins the digest. Dependabot can bump the digest with PR review.

**F-MN-3 — MED — No circuit breaker on nightly failure cascade.** If OAuth token expires or claude service degrades, EVERY nightly matrix cell fails. Alert fatigue + no signal. Disposition options: (a) workflow probes `claude -p "hello"` first; skips matrix if probe fails + opens auth ticket; (b) accept cascade. **Fold:** take option (a). Reuse the memory `feedback_oauth_verify_via_cheap_hello` pattern. 5-second hello probe before the 15-min matrix.

## Hyrum Wright — observable behavior becomes contract

Lens: What shape of the walking skeleton will Session B/C depend on? What becomes load-bearing once it ships?

**F-HW-1 — HIGH — Invariants library interface becomes depended-on.** Session B drivers (/sprint, /longrun prep, /temperance) will import `lite-runtime-invariants.sh` and call its functions. Once Session B lands, we cannot change the function signatures without breaking B. Disposition options: (a) ship invariants lib with narrow interface (3-5 functions, versioned); (b) ship as internal helpers (not stable interface); (c) delay stabilization to Session B. **Fold:** take option (a). Define 5 functions: `assert_no_absolute_paths <trace>`, `assert_bash_3_2_syntax <file>`, `assert_no_pyyaml_required <trace>`, `assert_no_playwright <trace>`, `assert_lite_runtime` (umbrella). Document contract in top-of-file header. Ousterhout deep module shape — narrow interface, implementation hidden.

**F-HW-2 — MED — Nightly workflow YAML becomes depended-on by adopter CI.** Adopters may copy the workflow pattern. YAML schema changes break their copies. Disposition options: (a) document "this workflow is bassclef-cli internal; adopters MUST NOT copy"; (b) ship a template at `templates/lite-adopter-smoke.template.yml` for adopters; (c) accept copy risk. **Fold:** take option (a) for Session A. Template work is Session A follow-on or Session B scope.

**F-HW-3 — LOW — Driver file naming convention becomes depended-on.** `scripts/tests/smoke-drive-e2e-<skill>.test.sh` pattern. Session B/C drivers will follow. Changing the pattern later breaks the glob in nightly workflow. Disposition options: (a) document pattern in CONTRIBUTING.md; (b) accept. **Fold:** take option (a). PR 1 adds one paragraph to CONTRIBUTING.md.

## Folds landing pre-code (RFC)

Six folds applied to walking skeleton shape before PR 1 opens:

1. **F-JC-1 → GHA OS matrix for CI + Dockerfile for local operator only.** Faster + more faithful.
2. **F-MN-1 → `docs/nightly-status.md` auto-generated by workflow.** One-file signifier.
3. **F-MN-2 → Pin node:20-slim to sha256 digest.** Reproducibility.
4. **F-MN-3 → Hello-probe before matrix.** Circuit breaker reuses PR #249 OAuth file-fallback pattern.
5. **F-HW-1 → Invariants lib narrow interface (5 functions, documented contract).** Ousterhout deep module.
6. **F-HW-3 → CONTRIBUTING.md names driver file pattern.** Convention over configuration.

## Folds deferred

- F-JC-2 — keep 5 atomic PRs per plan.
- F-HW-2 — template adopter workflow is Session A follow-on or Session B scope.
