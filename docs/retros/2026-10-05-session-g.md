## What to change next time

**Pre-flight read of ticket close times before authoring drivers.** If a ticket closed BEFORE the release claim, the close signal is peer-initiated and may not correlate to the cure landing where the driver reads. Add this check to the pre-flight step: for every ticket that a driver claims to characterize, check closedAt + compare to release publishedAt. Flag mismatches before relying on them.

**npm verify should use the workflow sigstore log, not npm view.** The workflow's Publish-to-npm step completes with sigstore attestation — authoritative + instant. `npm view dist-tags` lags by registry propagation. Future releases: cite the sigstore transparency log instead of the dist-tags result.
