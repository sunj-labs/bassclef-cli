## Assessment areas — 14 universal

### 1. Component architecture

- `src/commands/` — command entry-points (init, sync, migrate). Clean boundaries.
- `src/lib/` — shared libs (copy-substrate, manifest-io, write-safely, migrate). Deep modules per Ousterhout.
- `src/index.ts` — CLI dispatcher.
- `harness/docker/` — NEW top-level path for testing infrastructure (this session). Distinct from source per RFC-0001 R7.
- `scripts/` — bash operator scripts (smoke-*).
- **Verdict:** clean. Adding `harness/docker/` did not blur `src/` vs `scripts/` boundary.

### 2. Data flow

- `bassclef init` reads `dist/lite/**` bundle + writes to adopter's `.claude/**` + `docs/**` + config files.
- Docker harness (new) — same data flow but inside container. No divergence.
- **Verdict:** clean. Adopter data flow single-sourced through init walker per ADR-002.

### 3. Auth + security

- Cli itself uses NO auth. Reads public npm registry only.
- Docker harness passes ONLY `CLI_VERSION` + `ANTHROPIC_API_KEY` per RFC-0002 R9 anticorruption layer.
- No credential storage. No secrets in tarball (verified by npm-pack audit test).
- Container runs as unprivileged `adopter` user (uid=1000) per RFC-0002 R4.
- **Verdict:** clean. Saltzer-Schroeder least-privilege applied at container boundary.

- **Verdict:** clean. No proprietary dep. Failure modes: base image drift (pre-mortem-4 DN2).
