# Goal — cli 1.1.1 — make `bassclef init` report the truth

## Problem

`bassclef init` writes 379 files and then reports something else. Three
separate output defects, all in one file.

The init manifest records one file. Sync reads that manifest to know what
to check, so sync checks one file out of 379. The `--json` report goes to
stderr while human prose goes to stdout after it, so `tail -1` returns
prose. The JSON itself counts hooks and nothing else, so ten of the eleven
catalog families the 1.1.0 bundle ships go unreported.

## Goal

After this goal, an adopter script can trust three things. The manifest
names every file init wrote. `bassclef init --json` puts JSON on stdout as
the only stdout content. The JSON names every catalog family with a count.

## Evidence

- Source `src/commands/init.ts` L583: `writeManifest(targetDir, results)`
  receives only the config-composer results. The comment at L575-578
  excludes walker files on purpose.
- Source `src/commands/init.ts` L418: `process.stderr.write(JSON.stringify(report))`.
  Source L585-591 writes the folder reminder to stdout afterward.
- Source `src/commands/init.ts` L411-417: the report object carries
  `copied / declared / failed / scope_counts / tier` and nothing else.
- Source `src/commands/init.ts` L330-370 already classifies every copied
  entry into eleven families for the banner, then discards the result.

## Out of scope

- `bassclef list <family>` (cli#92) — a new surface, not a defect.
- Routing `.claude/*.md` root docs (cli#96) — blocked on upstream
  lite-manifest v1.7.0. Verified: tag v0.42.0 carries manifest_version
  1.6.1 with zero such entries.
- The sync postcondition failure (cli#97 / bassclef-upstream#1707). The
  fix lives upstream.
