## Design principles

**Norman — signifier.** Every count line names the type and the location. The reader knows what landed and where without guessing.

**Norman — feedback loop.** Refused-count line is always emitted, even when 0. Silence on 0 leaves the reader wondering "did that check run?" Explicit 0 confirms the check fired.

**Tufte — data-ink ratio.** Numbers first, prose second. No decoration. No emoji. Adopter scans left column, gets counts.

**Linus — adopter contract.** Banner shape is public. 1.1.1+ additions land as new lines. Existing lines never move. Existing counts never disappear (a count of 0 stays visible).

## Extension banners

### Refused files present (@risk L1, L3)

```
bassclef init: 3 files refused (path collision). Use --force to overwrite existing files.
```

### Verbose flag (`--verbose`)

Adds a section listing refused paths:

```
bassclef init: Refused files (3):
  .claude/skills/interview-me/SKILL.md — file already exists
  .claude/rules/testing.md — file already exists
  .claude/luminaries/kent-beck.md — symlink; target: /Users/adopter/vendored/beck.md
```

### JSON output (`--json`)

Extend existing structured line with per-type counts (unchanged consumer surface for hook counts; additive):

```json
{
  "schema_version": 3,
  "counts": {
    "hooks": { "declared": 24, "installed": 24, "project": 22, "user": 2 },
    "skills": 40,
    "rules": 63,
    "agents": 4,
    "luminaries": 32,
    "libs": 30,
    "adrs": 6,
    "templates": 5
  },
  "refused": 0
}
```

## Contract stability (@risk HW)

The banner shape becomes an adopter contract at 1.1.0. Adopters may pipe init output through `grep` for count parsing. Once shipped, count-line text is immutable:

- Line text `Installed N skills, N rules, N agents, N luminaries under <repo>/.claude/.` — fixed
- Line text `Installed N libs, N ADRs, N templates under <repo>/.` — fixed
- Line text `N files refused (path collision).` — fixed
- New type at 1.2.0+ → new line added; never inserted mid-existing block
