# Upgrading to `@thebassclef/core@0.1.0`

**Audience:** adopters on `@thebassclef/core@0.0.1` (name reservation) or `@thebassclef/core@0.0.2` (first init shape).

**Command:** `bassclef migrate`

**Time to run:** ~5 seconds.

---

## What changed at 0.1.0

The 0.1.0 release added 146 substrate files (skills + rules + hooks + luminaries + agents + standards). Prior versions shipped only the 3 config files (`.claude/settings.json`, `substrate.config.md`, `substrate.secrets.md`).

The `bassclef migrate` command upgrades an existing install without losing your config edits.

## Before you start

- Upgrade the CLI: `npm install -g @thebassclef/core@latest`
- Confirm the version: `bassclef --version` should print `0.1.0` or later
- **Recommended first run:** `bassclef migrate --dry-run` shows the plan without touching any files

## Two upgrade paths

Migrate picks the path automatically based on your install state.

### Path A — you already ran `bassclef init` at 0.0.2

Symptoms: you have a `.bassclef/init.manifest.json` with 3 file entries. Your project has `.claude/settings.json` and other config files you may have edited.

What migrate does:

- Reads your existing manifest to detect the 0.0.2 shape
- Computes SHA-256 hashes for your 3 config files (so future `bassclef sync` runs can tell adopter edits from template drift)
- Adds the 146 substrate files that are missing
- **Leaves your 3 config files untouched** — every byte you edited stays
- Rewrites `.bassclef/init.manifest.json` to the 149-entry shape

Sample output:

```
$ bassclef migrate
Ready to migrate to 0.1.0. Adds substrate files; preserves 3 existing config files.
Proceed? [y/N] y
bassclef migrate: 146 added; 3 preserved with existing content.
bassclef migrate: your substrate lives under .claude/. Add .claude/ to .gitignore if you have not.
```

### Path B — you reserved the name at 0.0.1 but never ran init

Symptoms: no `.bassclef/init.manifest.json` in your project directory.

What migrate does:

- Dispatches the full `bassclef init` flow for all 149 files
- Writes the fresh 0.1.0 manifest

Sample output:

```
$ bassclef migrate
bassclef migrate: no prior manifest detected. Running full init for 149 files.
bassclef init: 149 created, 0 unchanged.
bassclef init: your substrate lives under .claude/. Add .claude/ to .gitignore if you have not.
bassclef migrate: your substrate lives under .claude/. Add .claude/ to .gitignore if you have not.
```

## Options

| Flag | Behavior |
|---|---|
| `--dry-run` | Preview the plan without writing anything |
| `--verbose` | Print one line per file (not just the summary) |
| `--yes` | Skip the confirmation prompt (for CI + scripted upgrades) |
| `--allow-root` | Allow running as root (unusual; not recommended) |
| `--allow-any-dir` | Allow a target outside your home directory |
| `--dir <path>` | Target directory (defaults to current working dir) |

## Failure modes and cures

Every refusal message ends with a specific command you can run. The table below covers the common cases.

| Message | Cause | Cure |
|---|---|---|
| `unknown flag: --foo` | Typo in the argv | Correct the flag; run again |
| `refusing to run as root` | Root without `--allow-root` | Run as the project owner, OR pass `--allow-root` |
| `manifest is not valid JSON` | Manual edit corrupted the manifest | Repair manually, OR run `bassclef init --force` to reset |
| `manifest schema version ... is newer` | Your manifest was written by a newer `@thebassclef/core` | Upgrade the CLI to at least that version |
| `adopter state does not match 0.0.x or 0.1.0` | Manifest present but shape is neither known form | Reinstall `@thebassclef/core` then rerun |
| `refused (symlink)` | Target path is a symlink | Remove the symlink; rerun |
| `refused (parent not writable)` | Target directory permissions | Check + fix directory permissions |

## Recovering from a mid-migration crash

If you interrupt migrate mid-run (Ctrl-C, laptop closed, power loss), some files may have landed while the manifest was not yet rewritten. On the next run:

- Migrate detects the hash mismatch and reports both possible causes: "You edited the file since migration started" OR "A prior migration did not finish"
- Cure: `bassclef sync --replace-edits --force` re-baselines against the current template

Your original config files are still on disk and untouched. Nothing gets destroyed.

## About the version bump

The 0.1.0 release adds substrate files without breaking any prior CLI verb or exit code. Under semver that qualifies as a MINOR bump.

**Adopter migration ships as MINOR** is the precedent this release documents (RFC L3 refinement). Future migrations that touch adopter-visible state MUST bump MINOR at minimum. PATCH releases are reserved for bug fixes that require no adopter action.
