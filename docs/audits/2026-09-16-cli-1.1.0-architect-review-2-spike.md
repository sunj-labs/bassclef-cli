## Findings (4 total: 1 AMBER, 3 GREEN)

### F-8 — Identity path mapping simplifies design; ADR-057 D1 remains as init contract

- **Severity.** GREEN
- **Lens.** boring-tech + mechanism-fidelity
- **My claim.** Learning 1 (identity path mapping) is the simplest correct design.
- **Evidence.** Spike step 4 shows `copyFileSync(join(sibling, e.path), join(distRoot, e.path))` works with 0 transformation.
- **Why the evidence supports the claim.** Simpler code = fewer failure modes. ADR-057 D1 target-path prefixes still document the init walker's routing intent even though prepublish doesn't need them. Keep ADR-057 as-is; document the split in decomposition.
- **Cure.** Update decomposition § "Catalog reader" interface: "Copy `<sibling>/<entry.path>` → `<distRoot>/<entry.path>` (identity mapping)". Note that init walker uses ADR-057 path-prefix routing, not manifest type field.

### F-9 — Init walker skips manifest read at init time; correct simplification

- **Severity.** GREEN
- **Lens.** Ousterhout deep module + Rich Hickey simple-made-easy
- **My claim.** Init walker routes by path prefix without reading `lite-manifest.json` at adopter machine.
- **Evidence.** Spike Learning 2: files land at `.claude/skills/**` etc. in `dist/lite/`. Init walker walks the tree, sees the prefix, routes.
- **Why the evidence supports the claim.** No init-time manifest dependency = smaller adopter surface. Fewer things to fail-loud about. ADR-057 D1 is still the init contract (routing table), but the walker consults its own hardcoded prefix map, not the runtime manifest.
- **Cure.** Note in decomposition § "Walker classifier": `decisionsForFile` extends with path-prefix rules; no manifest dependency at init time. Manifest is prepublish-only.

### F-10 — Collision surface with existing DIST_TEMPLATE_FILES is empty today; add build-time assertion

- **Severity.** AMBER
- **Lens.** Hyrum's Law + Nygard fail-loud
- **My claim.** Spike Learning 3 says no collision between manifest entries and existing prepublish templates. That is TRUE today. Tomorrow, if upstream adds a root-doc named `whereami.md`, the collision surfaces silently.
- **Evidence.** Spike step 6 sampled root-doc entries: AGENTS.md, CLAUDE-lite.md, CODE_OF_CONDUCT.md, CONTRIBUTING.md, README.md, SECURITY.md. Existing dist templates: CLAUDE.md, whereami.md, .gitignore, .bassclef-source.json. No overlap.
- **Why the evidence supports the claim.** Silent collision at build time = adopter gets a corrupted bundle. Fail-loud is cheap: intersection check on entry paths vs DIST_TEMPLATE_FILES set. Nygard would insist.
- **Cure.** Add Step 6 code: `assertNoManifestCollisions(manifest, DIST_TEMPLATE_FILES)` at start of prepublish extension. Throw `CopyFailure` kind `ManifestCollision` if any entry.path is in DIST_TEMPLATE_FILES.

### F-11 — Bundle size growth (5x) is quantified and safe

- **Severity.** GREEN
- **Lens.** Ishikawa Material
- **My claim.** Bundle grows from ~180KB compressed (1.0.4) to ~200-400KB compressed (1.1.0). Well under npm limits.
- **Evidence.** Spike Learning 4 estimate. Real number lands at Step 6 code time when actual tarball builds.
- **Why the evidence supports the claim.** No design blocker. Adopter install time grows by seconds. Note in changelog per L2 discipline (banner + PR body count table).
- **Cure.** None design-side. Step 9 changelog entry names the size delta.
