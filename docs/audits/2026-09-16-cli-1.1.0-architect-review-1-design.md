### F-1 — ADR-057 type table misses 3 manifest types

- **Severity.** BLOCK
- **Lens.** Hyrum contract completeness + mechanism-fidelity
- **Where.** `docs/adrs/ADR-057-lite-catalog-destination-path-invariant.md` D1 table
- **My claim.** ADR-057 D1 covers 9 types plus 2 hook sub-cases. The manifest carries 12 distinct type values.
- **Evidence.** `python3 -c "..."` on `lite-manifest.json` v1.6.1 returned: standard(72), rule(63), skill(40), luminary(32), hook(29), lib(18), template(10), script(7), adr(6), root-doc(6), presence-template(5), agent(4). ADR-057 D1 table names hook, skill, rule, agent, luminary, lib, adr, standard, template. Missing: **script**, **root-doc**, **presence-template**.
- **Why the evidence supports the claim.** ADR-057 D3 says "unknown type → walker refuses to route (exit 5)." If the manifest ships 7 script + 6 root-doc + 5 presence-template entries with types not in the table, prepublish blocks 18 files. The bundle would be incomplete.
- **Cure.** Amend ADR-057 D1 to include three more rows:
  - `script` → project scope → `$CLAUDE_PROJECT_DIR/scripts/` (adopter-runnable helpers)
  - `root-doc` → project scope → `$CLAUDE_PROJECT_DIR/` (repo-root files: CLAUDE-lite.md, README.md, AGENTS.md, CONTRIBUTING.md, CODE_OF_CONDUCT.md, one more)
  - `presence-template` → project scope → `$CLAUDE_PROJECT_DIR/presence/install/` (rename from existing `template` row OR keep both distinct; my read: `template` → `$CLAUDE_PROJECT_DIR/templates/` for the 10 general templates; `presence-template` → `$CLAUDE_PROJECT_DIR/presence/install/` for the 5 install helpers)

Also update the count reference in the count-banner section: 40 skills, 63 rules, 4 agents, 32 luminaries, 18 libs, 6 ADRs, 10 templates, 5 presence-templates, 72 standards, 6 root-docs, 7 scripts, 29 hooks (24 declared + 5 undeclared based on 1.0.4 census). Total non-hook = 263; plus 29 hooks + hook dual-writes = 292+38 = ~330 file writes at init time.

### F-3 — UC-init-lite-catalog step 8 assumes Claude Code skill discovery mechanics

- **Severity.** AMBER
- **Lens.** Ishikawa Machine (external tool behavior)
- **Where.** `docs/use-cases/UC-init-lite-catalog.md` step 8 + main-scenario ending
- **My claim.** UC step 8 asserts "Types `/skills`. Sees 40 skills registered." That depends on Claude Code registering skills from `$CLAUDE_PROJECT_DIR/.claude/skills/` at SessionStart. The registration mechanism is external.
- **Evidence.** No test in the risk ledger (Steps 5, 10) verifies Claude Code actually registers skills from that path. UC assumes but does not prove.
- **Why the evidence supports the claim.** If Claude Code's discovery mechanism changes (a Claude Code release could move the discovery to `~/.claude/skills/`), all 40 skills at project scope would be invisible. UC would still pass its filesystem checks but Sam's demo would fail.
- **Cure.** Step 10 cold-adopter smoke MUST run `/skills` (or equivalent) inside a live Claude Code session and count entries. That's already implied by Cockburn walking skeleton (Ck row in ledger). Make it explicit in the UC: step 8 sub-clauses name that /skills output ≥ 40 as an observable postcondition.

### F-4 — Preflight harness scope-creeps toward general distribution tool

- **Severity.** AMBER
- **Lens.** boring-tech bias + Ishikawa Method
- **Where.** `docs/decompositions/2026-09-16-cli-1.1.0-lite-catalog.md` § "Preflight harness"
- **My claim.** The preflight harness lists 6 checks. Check 4 (file-count delta vs prior-tag baseline) requires reading a prior npm tarball. That is a new external dependency for cli's build path.
- **Evidence.** Decomposition Check 4: "File-count delta vs prior-tag baseline within tolerance." No mechanism named for fetching the prior tag; no timeout, no fallback.
- **Why the evidence supports the claim.** If the check depends on network to npm registry (or GitHub), it adds a network dependency to prepublish. 1.0.x prepublish is offline-capable. Adding a network hop expands scope.
- **Cure.** For 1.1.0, drop Check 4 from preflight OR mark it advisory-only (warning, not BLOCK). Compare file count against last tag in the LOCAL git checkout (offline). Full manifest-vs-registry parity moves to the bassclef-upstream substrate cure task, not the 1.1.0 prepublish path.
