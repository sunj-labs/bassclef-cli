## Learnings — real surprises

### Learning 1 — Path mapping is identity

**Discovery.** `entry.path` in the manifest IS the target-relative path under `dist/lite/`. Prepublish does `copyFileSync(join(sibling, e.path), join(distRoot, e.path))` for every entry. No transformation needed.

**Impact on design.** ADR-057 D1's "target-path prefix" column is REDUNDANT for prepublish. Prepublish uses `entry.path` directly. The type column matters only for the INIT walker to route to user vs project scope after the file is in the bundle.

**Cure.** ADR-057 stays as-is (documents init walker routing per Hyrum). Prepublish spec simplifies to "copy every entry at entry.path". Update decomposition § "Catalog reader" interface to reflect the identity mapping.

### Learning 2 — Init walker can route by path prefix, not manifest type

**Discovery.** Since files land at `.claude/skills/**`, `.claude/rules/**` etc. in `dist/lite/`, the init walker at adopter machine can route by PATH PREFIX. It doesn't need to read `lite-manifest.json` at init time.

**Impact on design.** Walker adds simple path-prefix rules to `decisionsForFile`:
- `.claude/skills/**` → project scope (single-write per 1.0.4 logic seam)
- `.claude/rules/**` → project
- `.claude/agents/**` → project
- `.claude/luminaries/**` → project
- `lib/**` → project
- `scripts/**` → project
- `standards/**` → project
- `templates/**` → project
- `presence/install/**` → project
- `architecture/decisions/**` → project
- root-docs (top-level files matching manifest root-doc set) → project

Existing hook logic unchanged (dual-scope + declared/undeclared per 1.0.4).

**Cure.** Decomposition § "Walker classifier" already names path-prefix routing. No change needed. But: init walker does NOT need to read the manifest. That simplifies the init contract.

### Learning 3 — 6 root-docs live at repo root — potential collision with template files

**Discovery.** Manifest has 6 `root-doc` entries: AGENTS.md, CLAUDE-lite.md, CODE_OF_CONDUCT.md, CONTRIBUTING.md, README.md, SECURITY.md. Existing prepublish already lays down CLAUDE.md (not CLAUDE-lite.md — different file) and other repo-root templates.

**Impact on design.** Two possible collisions:
- Existing `CLAUDE.md` template (from `copyDistTemplates`) vs manifest's `CLAUDE-lite.md` (from catalog) — different filenames, no collision
- Existing `.gitignore` (renamed from `gitignore` by init.ts) vs any manifest entry — no `.gitignore` in manifest root-docs
- Existing `.bassclef-source.json` (init.ts writes) vs manifest — no collision
- `whereami.md` (dist template) — no collision with manifest

No collisions surfaced. But: `readme.md` under manifest vs `README.md` in cli's dist templates — check case sensitivity on macOS APFS (case-insensitive by default). Cli's dist has no README.md today. Manifest's README.md lands cleanly.

**Cure.** No collision cure needed for 1.1.0. Add a Step 6 code assertion: no manifest entry.path collides with the existing `DIST_TEMPLATE_FILES` set. If collision surfaces, fail loud at build.

### Learning 4 — Bundle size grows from 108 files to ~400

**Discovery.** Cli 1.0.4 bundle: 68 files (dist tree count). Cli 1.1.0 bundle: 68 + 292 = ~360 files. npm tarball grows accordingly.

**Impact on design.** Bundle size is well under npm's 100MB soft limit. Compressed tarball for cli 1.0.4 was ~180KB. Cli 1.1.0 tarball estimate: 800KB-1.5MB uncompressed / 200-400KB compressed. Acceptable.

**Cure.** No design change. Note in changelog: adopter tarball size grows ~5x. Adopter install time grows by seconds, not minutes.
