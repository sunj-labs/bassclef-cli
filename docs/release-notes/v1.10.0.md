# v1.10.0 — fifteen hooks that shipped for two months and never ran

**Prepared** 2026-11-08 · **Bassclef substrate** `v1.12.0`

## What this means for you

Install or upgrade, and 46 hooks are wired into your project instead of 31.

The fifteen new ones were already on your disk. They have been since
2026-09-15. They were installed and never connected to anything, so they sat
there looking exactly like hooks that work. Upstream's v1.12.0 found and fixed
the reader that caused it.

Among what turns on: a check before an architecture decision lands, a guard on
destructive shell commands, a scrub on PR titles and bodies, a reviewer
dispatch check, and a gate on multi-step branches.

**Seven of the fifteen can stop a tool call. Eight only warn.** That split is
worth knowing before one surprises you. `destructive-command-guard` prints a
loud banner and does not stop anything — filed upstream as `#2445`.

## The part worth reading if you build on this

**A local build and a published build used to disagree, silently.** The
packager read whichever copy of the framework sat next to it on disk; CI read
the pinned version. That produced 46 hooks on a laptop and 31 in the package,
and no line of output mentioned it.

The packager now reads `.bassclef-pin`, checks the source it found against that
pin, and refuses when they disagree. Every run prints what it built from:

```
bundle source: /path/to/bassclef
  resolved via: .bassclef-pin
  pin: v1.12.0
  source release_tag: v1.12.0
dist/lite/.claude/settings.json emitted 46 hook entries
```

The same fault had a third instance nobody had noticed: the PR-checks workflow
pinned `v1.1.1` while the pin file said `v1.11.1`. One character apart, 27 days
apart, both real. The entire test suite was validating a package built from one
version of the framework while releases shipped another.

## Publish-gate fixes

Neither reaches an adopter. Both matter if you maintain this.

**The authorisation record survives a branch switch.** It was tracked in git,
so `git reset --hard` rewrote it — which is how an operator's approval for an
unattended publish was lost on 2026-11-08. The record now sits outside the
repository. A new `audit` verb reads the log in order and reports any gate
opening that never closed.

**`trust` is a real verb.** It used to be another spelling of `off`, with the
gate's restoration resting on a sentence in a skill file asking an agent to do
it later. It now writes a marker with an expiry, and `rearm` closes the window
from that marker without waiting for the publish to finish.
