# v1.9.12 — your first commit stops getting blocked

**Released** 2026-10-08 · **Bassclef substrate** `v1.9.3`

## What this means for you

If you installed bassclef and then tried to commit, checks would sometimes block you over files bassclef itself had just written. That is fixed.

`bassclef init` now keeps a list of the files it wrote. The checks read that list and skip those files. They still check anything you wrote.

## What changed

- `bassclef init` writes `state/install-written-paths.json`, a record of what it installed.
- Two checks read that record and no longer fire on bassclef's own files.
- Added tests that run against the real installed package, so this cannot quietly come back.

## Do you need to do anything?

No. If you were working around this by skipping checks, you can stop.
