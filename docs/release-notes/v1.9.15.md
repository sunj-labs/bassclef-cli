# v1.9.15 — a slow startup step stops timing out

**Released** 2026-10-12 · **Bassclef substrate** `v1.9.6`

## What this means for you

At the start of every session, bassclef records which files it installed. It used to do that one file at a time, 451 times, and give up partway. You ended most sessions with about 8 of 451 files recorded.

The checks that read that record were then working from a list that was almost empty. Now the whole list gets written at once.

## What changed

- The record is built in one pass instead of 451 separate steps.
- A session-start step rebuilds the record when it is missing.

## Do you need to do anything?

No. A fresh install gets the fix through `bassclef init`. An existing install gets it at your next session.

## Notes

Nothing in bassclef-cli changed. Only the bundled substrate moved.
