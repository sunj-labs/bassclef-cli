## Primary risks (v1)

### N1 — Recursive walk misses a nested file

**Lens:** Nygard  
**Risk:** The new walker recurses into subdirs; if the recursion has a bug (early-return, wrong stat), a file in `session-reflection.d/` is silently skipped.  
**Fold:** Tier 0 test asserts BOTH top-level `trace-helper.sh` AND nested `session-reflection.d/fragment.sh` land in the tarball. Fixture covers both cases.

### N2 — Postflight passes but tree is empty

**Lens:** Nygard  
**Risk:** Filtered settings.json has 0 declared commands (edge case), so postflight passes trivially with a truly empty tree.  
**Fold:** Existing check at L244-249 already fires `fail(hookCount < 1)`. Verify the check runs regardless of settings.json shape.

### F1 — Fixture drifts from real sibling shape

**Lens:** Feathers  
**Risk:** The fixture at `tests/harness/fixtures/sibling-with-helpers/` uses a hand-picked shape; upstream v0.43.0 could add a new pattern the fixture does not cover.  
**Fold:** Fixture documents the shape it characterizes at the top of every file. Any upstream tree shape not in the fixture is a follow-on issue.

### B1 — RED commit lands with the wrong shape

**Lens:** Beck  
**Risk:** The RED commit adds tests, but they assert on the wrong shape and pass falsely.  
**Fold:** RED commit MUST show the suite failing at the new tests. Verify with `npm test 2>&1 | grep FAIL` before commit.

### C1 — Walking skeleton fixture too thin

**Lens:** Cockburn  
**Risk:** Fixture has one file + one nested dir; real sibling has 24 + 1 dir with 2 fragments. Skeleton missing edge cases.  
**Fold:** Fixture matches real shape (24 top-level, 1 fragment dir with 2 fragments). Later PRs can extend.

### L1 — Removing a shipped file breaks adopters

**Lens:** Linus  
**Risk:** Once 1.0.3 ships every file, any subsequent removal is a covert break of the adopter contract.  
**Fold:** Document in CHANGELOG under 1.0.3 that file removals require an ADR-031 compat window. Sister ticket bassclef-upstream#1684.

### L2 — Cli-side filter re-introduced later

**Lens:** Linus  
**Risk:** A future maintainer, unaware of this fix's motivation, adds a cli-side filter for perceived "cleanup" reasons.  
**Fold:** Add a header comment to `copyHookTreeRecursive` naming the anti-pattern with reference to this risk ledger + cli#87.

### L3 — Sibling pin drifts

**Lens:** Linus  
**Risk:** Workflow pin (v0.42.0) can move via ADR amendment; if a future pin points at a tag with different bundle shape, the fix's assumptions may break.  
**Fold:** Workflow's `Assert pinned bassclef tag resolves` step (L130-143) already fails loud on tag drift. No cli-side action needed.

## RFC-derived risks (v2 additions)

### HT-1 — Duplicate source of truth on "what ships"

**Lens:** Hunt & Thomas  
**Risk:** Settings.json commands + tree files both encode "what ships." They can drift.  
**Fold:** ADR-007 amendment names the two-source split explicitly. Postflight is the runtime check. Upstream owns keeping them in sync.

### HT-2 — Tarball contents not discoverable from cli repo

**Lens:** Hunt & Thomas  
**Risk:** Cli reader cannot list the tarball's hook files without cloning the pinned sibling.  
**Fold:** ADR-007 amendment adds a one-line pointer: "the tarball's content is fully determined by the sibling tag pinned in `.github/workflows/publish.yml` — read that tag's `dist/lite/.claude/hooks/` for the truth."

### ST-1 — Argument's three parts all load-bearing

**Lens:** Toulmin  
**Risk:** The "tarball contents are correct" argument rests on: sibling pin correct + walker preserves tree + postflight catches drift. Any one part missing → argument falls.  
**Fold:** CHANGELOG under 1.0.3 names all three parts. Risk ledger rows track each independently (L3, N1, N2 above).

### ST-2 — Postflight cannot detect stale settings.json

**Lens:** Toulmin  
**Risk:** If upstream's settings.json declares a command that its tree DOES ship, cli passes; if upstream's settings.json OMITS a command that SHOULD be there, cli cannot detect it.  
**Fold:** Cannot solve at cli. Document as upstream's responsibility.

### HW-1 — File list becomes Hyrum-contract with adopters

**Lens:** Hyrum  
**Risk:** Adopters may inspect the tarball, notice `trace-helper.sh`, and source it from custom hooks. Removing the file later breaks those adopters.  
**Fold:** L1 above already covers. Cross-reference bassclef-upstream#1684.

### HW-2 — Executable bit becomes Hyrum-contract

**Lens:** Hyrum  
**Risk:** Adopters may rely on shebang + exec bit rather than `bash <path>`. Stripping exec bit later is a covert break.  
**Fold:** Cli preserves exec bit; upstream drift is the risk. Document only; no cli action.

### RH-1 — "Simpler" not defined

**Lens:** Rich Hickey  
**Risk:** Primary consult called new shape "simpler" without defining the word.  
**Fold:** Goal doc "Fix" section rewords: tree-copy takes ONE input (sibling tree); command-filter took TWO (tree + settings). One-input is simpler.

### SS-1 — Symlink refusal must fire at nested depth

**Lens:** Saltzer-Schroeder  
**Risk:** Recursive walk must `lstat` every entry — nested included. Fixture and test must cover nested-symlink case.  
**Fold:** Test list adds "symlink at nested depth fails loud." Fixture includes a nested symlink case.

### SS-2 — Helper renames upstream break adopters silently

**Lens:** Saltzer-Schroeder  
**Risk:** If upstream renames a helper (e.g., `trace-helper.sh` → `trace.sh`), cli ships the new name; adopters sourcing the old name break.  
**Fold:** Cannot solve at cli. Upstream ticket bassclef-upstream#1684 covers the shared-construct amendment discipline.

### SS-3 — No signature check on sibling tree

**Lens:** Saltzer-Schroeder  
**Risk:** Cli trusts sibling contents implicitly; a malicious commit between pin-time and publish-time could inject content.  
**Fold:** Cannot solve at cli without signed commits or content-hash verification. Document; deferred to a future signed-commits ADR.
