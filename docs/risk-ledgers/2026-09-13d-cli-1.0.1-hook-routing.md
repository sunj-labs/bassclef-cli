## v2 council-lens findings (folded per RFC disposition)

### Linus Torvalds — adopter contract

- **L1 (HIGH)** — cli 1.0.0 → 1.0.1 upgrade path introduces user-scope writes for the first time. Adopters see unexpected files at `~/.claude/hooks/`.
   - **Engineering fold**: New check in InitDispatcher — if cli 1.0.0 `.bassclef/init.manifest.json` exists AND has no user-scope entries, print an advisory line: `"cli 1.0.1 introduces user-scope hook installation at ~/.claude/hooks/. This is new since 1.0.0. Continue? (y/N)"`. Default answer on non-interactive stdin: `y` (matches CI + `--force` shape). Adopter can pass `--yes` to skip prompt.
   - **Owner**: InitDispatcher `checkPriorInstall(targetDir)` new function
   - **Tests**: +2 Tier 0 (prompt fires when 1.0.0 manifest present; prompt skips when 1.0.0 manifest absent OR `--yes` passed)
   - **Spec update**: acceptance row added — "First-run 1.0.1 install on a 1.0.0-installed repo prints the advisory + waits for confirmation OR proceeds under `--yes`."
   - **CHANGELOG**: `**Behavior change:** cli 1.0.1 writes hook binaries to ~/.claude/hooks/ (user scope). cli 1.0.0 did not. Pass --yes to skip the first-run prompt.`

- **L2 (HIGH)** — manifest schema addition breaks strict readers.
   - **Engineering fold**: Add `schema_version: 2` field to `.bassclef/init.manifest.json` at top level. Sync reader tolerates both `1` (implicit — no field) + `2` (explicit). Add `schema_version` to the template output.
   - **Owner**: `src/commands/init-templates/manifest-json.ts` + `src/lib/manifest-io.ts`
   - **Tests**: +2 Tier 0 (v1 manifest read succeeds; v2 manifest read succeeds)
   - **Spec update**: acceptance row added — "manifest.json schema_version equals 2 after cli 1.0.1 init."

- **L3 (LOW)** — sync must skip user-scope entries.
   - **Engineering fold**: Tier 0 test in `src/commands/sync.test.ts` asserts sync on a mixed-scope manifest does not detect user-scope edits.
   - **Tests**: +1 Tier 0
   - **Spec update**: none (test-only)

### Hyrum Wright — observable behavior

- **H1 (HIGH)** — banner shape lock-in.
   - **Engineering fold**: Add `--json` flag to `bassclef init`. When present, print structured stderr line `{"copied": 24, "declared": 24, "scope_counts": {"user": 2, "project": 22}}` alongside human banner. Human banner shape stays operator-facing; JSON shape is the stable machine-readable surface.
   - **Owner**: `src/commands/init-argv.ts` (new `--json` flag) + `src/commands/init.ts` (`printJsonReport` branch)
   - **Tests**: +2 Tier 0 (JSON emitted when flag set; JSON absent when flag omitted)
   - **Spec update**: acceptance row added — "bassclef init --json emits structured line with copied/declared/scope_counts fields."

- **H2 (MEDIUM)** — `CopyResult.scope` additive shape.
   - **Engineering fold**: Keep `scope` as REQUIRED (not optional) in `CopyResult.copied` entries. Internal type change only — no adopter-facing consumer today. If Hyrum bite later, we version the CopyResult shape.
   - **Owner**: Type change in `src/lib/copy-substrate.ts`
   - **Tests**: existing tests updated (spec change, not additive)

- **H3 (MEDIUM)** — exit codes reused for new failure classes.
   - **Engineering fold**: CHANGELOG entry documents that exit 1 now covers `EnvironmentIncomplete` + `SudoBypassRefused`; exit 5 now covers `UnknownScopePrefix`; exit 2 now covers `PathTraversalRefused` + banner count mismatch. No code change.
   - **Owner**: CHANGELOG at release time
   - **Tests**: existing exit code tests unchanged

- **H4 (LOW)** — WriteError semantics extend to user-scope. Silent-accept per RFC.

### Frederick Brooks — conceptual integrity

- **B1 (HIGH)** — walker signature leaks single-scope shape.
   - **Engineering fold**: Keep current `copySubstrate(targetDir, opts)` signature. Document in spec that ScopeRouter internally resolves user-scope from `$HOME`; no new argument.
   - **Owner**: Spec update; NO code change
   - **Tests**: NONE
   - **Rationale for accepting b (not a)**: The refactor cost per B1 option (a) would be ~30 lines of API surface change with no functional gain. Every consumer (tests, InitDispatcher) would need the update. Conceptual integrity here is served by making ScopeRouter the sole surface knowing about user-scope; the walker entry-point stays project-scoped. Documented in spec.

- **B2 (MEDIUM)** — split failure lexicon (CopyFailure vs WriteError). Documentation-only per RFC.
   - **Engineering fold**: Spec table added: "CopyFailure kinds cover discovery + classification failures (ManifestMissing, SchemaIncompatible, UnknownScopePrefix, EnvironmentIncomplete, SudoBypassRefused, PathTraversalRefused). WriteError kinds cover filesystem mediation failures (AlreadyExists, SymlinkRefused). Both types carry a `kind` + remediation."
   - **Owner**: Spec update
   - **Tests**: NONE

- **B3 (MEDIUM)** — class count doubles. Silent-accept — cross-cutting audit in GRASP decomp handles.

### Don Norman — signifier + feedback

   - **Owner**: `src/lib/write-safely.ts` error path
   - **Tests**: +1 Tier 0 (symlink error message contains target)

- **N3 (MEDIUM)** — subsumed by N1 above (two-scope explicit in banner)
