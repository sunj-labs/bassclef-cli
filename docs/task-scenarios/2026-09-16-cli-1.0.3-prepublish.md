## Persona touchpoints

### ColdAdopter (fresh macOS profile)

**User story CA-1.** *As a first-time adopter,* I want `npm install -g @thebassclef/lite && bassclef init && claude` to succeed on the first try, *so that* I do not have to debug someone else's hook wiring on my first day.

- Acceptance: `claude` opens without a red SessionStart error block
- Acceptance: `/skills` renders the catalog
- Signal of regression: any `source: No such file or directory` line at SessionStart

**User story CA-2.** *As a re-testing adopter,* I want `smoke-reset.sh --cold` followed by a fresh install to give me the same clean state every time, *so that* I can iterate on my own workflow without residue.

- Acceptance: two consecutive `--cold` runs both end at "reset complete"
- Signal of regression: hook file count drift between runs

### BassclefCliMaintainer (this session)

**User story BM-1.** *As the cli maintainer,* I want the prepublish script to fail LOUD when the sibling tree is missing helpers OR the settings.json filter references a hook that has no binary, *so that* no broken tarball reaches npm.

- Acceptance: Nygard-style `fail()` on either condition with a specific error line
- Signal of regression: silent skip of any file

**User story BM-2.** *As the cli maintainer,* I want a Tier 0 fixture that pins the tree-copy behavior against a known sibling shape, *so that* future edits to `copyHookBinaries` cannot silently drop files again.

- Acceptance: `tests/harness/fixtures/sibling-with-helpers/` contains `trace-helper.sh` + a `session-reflection.d/` fragment; test asserts both land in the tarball
- Signal of regression: fixture drift without test update

## Scenario walkthroughs

### Scenario 1 — Happy path publish (BM-1 satisfied)

1. Publish workflow checks out sibling public bassclef at v0.42.0 pin
2. Prepublish reads sibling `dist/lite/.claude/hooks/` — 26 files (24 top-level + 2 in `session-reflection.d/`)
3. Recursive copy lands all 26 in cli's `dist/lite/.claude/hooks/`
4. Postflight verifies every declared command has a matching binary (all pass)
5. `npm pack` ships the tarball
6. Adopter installs; hooks work at first `claude` session

### Scenario 2 — Upstream drops a declared hook (BM-1 fail-fast)

1. Sibling checkout points at a tag where upstream removed `pre-build-gate.sh`
2. Filtered settings.json still declares `pre-build-gate.sh` as a command (drift)
3. Postflight walks declared commands, notices no matching binary
4. Prepublish exits non-zero: `postflight: settings.json declares pre-build-gate.sh but no matching binary in tree`
5. `npm pack` does not run
6. Publish workflow job fails; operator sees the specific missing name

### Scenario 3 — Sibling adds a new helper (CA-1 satisfied)

1. Upstream ships v0.43.0 with a new `some-new-helper.sh` under `dist/lite/.claude/hooks/`
2. Cli's prepublish walks the tree, copies it
3. Postflight logs INFO: "extra file `some-new-helper.sh` not in settings.json (helper)"
4. Tarball ships the new file
5. Any bundled hook that sources `some-new-helper.sh` at runtime finds it in place

### Scenario 4 — Symlink in the sibling tree (BM-1 refusal)

1. Some future upstream commit places `dist/lite/.claude/hooks/trace-helper.sh` as a symlink to `../../trace-helper.sh`
2. Prepublish walks the tree, detects the symlink via `lstat`
3. Prepublish exits non-zero: `refusing to follow symlink at dist/lite/.claude/hooks/trace-helper.sh`
4. Publish workflow job fails
5. Cli maintainer knows upstream introduced a symlink they need to reject or resolve

### Scenario 5 — Adopter re-runs smoke on cold-adopter-1 (CA-2 satisfied)

1. Adopter runs `smoke-reset.sh --cold` — clean state
2. Adopter runs `npm install -g @thebassclef/lite@1.0.3` — 1.0.3 installs
3. Adopter runs `bassclef init` — 26 hooks land across two scopes
4. Adopter runs `claude` — opens clean
5. Adopter re-runs `smoke-reset.sh --cold` — same clean state (idempotent per --cold discipline)
