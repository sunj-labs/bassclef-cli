## Retrospective

### Went well

- **Peer exchange discipline held.** Every peer message went to draft first, previewed with operator, then sent. Two peer rounds ended with peer filing #1880 and confirming #1860 in v1.1.2 — both concrete outcomes for adopters.
- **v1.5.0 → v1.5.1 recovery was fast.** Failed publish caught 30s in via `tests/version-sync.test.ts`. Fix landed in one PR with proper markers, tests passed locally before push (this time), publish shipped clean.
- **Docker harness verified end-to-end.** Ship 1 tail question got answered with real evidence (28 wired hooks, 0 leaked, exclusions boundary clean). Peer's original framing was misdirected; our repro caught the doc-code drift class.
- **Ticket + epic filing was proactive.** Four issues filed (#192, #193, #194, #195) capture the class-level fixes for release pipeline + harness ergonomics before the next cycle.
- **Assert-verify discipline caught peer misdirection.** The 84-line peer message reported findings with source citations and a falsification test. Peer ran the falsification test and found the real class (doc-code drift). Discipline worked as designed.

### Harder than expected

- **v1.5.0 publish miss was self-inflicted.** I hand-edited `package.json` alone. `scripts/bump-version.mjs` exists specifically to touch all four files. I did not use it. The tests that exist to catch this class (`tests/version-sync.test.ts`) fire only on `release: published`, so the miss was caught post-tag. Same class went unnoticed on v1.4.1 sync (used manual edits too; passed only because bump was reactive not proactive).
- **Approval-gate visibility gap surfaced late.** Every publish cycle this session paused at the `npm-publish` environment gate. Operator was not looking for a notification because none was ever set up. My "approve at the gate" prompts assumed operator was watching Actions. They were not.
- **Docker harness invocation had to be reconstructed from CI workflow.** No `scripts/run-harness.sh` wrapper. Every manual harness call means reading `.github/workflows/docker-smoke.yml` for the `docker build` + `docker run` args.
- **Peer's original ask was framed against a documented label that did not exist in code.** Cost real turns to run the check, report, get correction, verify the real check. Both sides working from stale docs.

### Change for next time

- **Use `npm run bump patch|minor|major` for every version change.** Never hand-edit `package.json`. Rule extends to any repo that ships `bump-version.mjs`.
- **Run `npm test` locally before pushing a version bump PR.** Skipping local tests was the actual root cause. Prior v1.4.1 sync did the same thing and passed by accident.
- **Ship epic #194 story 1 first** — pre-publish check job on PR events. Closes the class that bit us this session.
- **Ship epic #195 story 1 next** — `scripts/run-harness.sh` wrapper. Every future harness call becomes one command instead of three.
- **Set up GitHub deployment notifications** per ticket #192. Non-negotiable for autonomous session pacing.
- **When peer asks about a documented label, verify the label matches the code** before running the check. Two-way doc/code check saves round-trips.
